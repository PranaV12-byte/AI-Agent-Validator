# SafeBot UI foundation

This foundation translates the accepted Test core, rule modal, Profile, and Security references into reusable UI for staged review. The development preview is not a working Test, protection, connection, or account flow. Its sample values are synthetic, and its forms do not send or save anything.

## Direction

- Use a quiet, light surface with deep blue ink and a clear cobalt primary action.
- Keep the shell text-led: Test, Protection, Activity, and Connect in the workspace navigation, with Account settings and Help & feedback at the bottom.
- Keep the SafeBot wordmark casing and a 12px mark-to-word gap. The Frame mark is an SVG with a 2-unit internal gap in its 32-unit view box.
- Prefer visible, thin boundaries and compact content. Cards and modal use 16px corners; fields and buttons use 8px. A 12px control-radius token is available for a future grouped control, while the current tabs use a simple underline treatment.
- Avoid gradients, shields, decorative icon clutter, and broad legacy recoloring.

## Layout and responsive behavior

At wide widths the shell uses a left rail and a flexible content area. The rail starts expanded with text labels; its control can collapse it to an 80px icon rail while preserving accessible link names, selected state, hover/focus labels, and the Account/Help footer. Sidebar items scroll independently on short desktop viewports so the toggle and footer remain reachable. At 720px and below, desktop collapse styling is reset and the wordmark remains visible. A separate closed-by-default disclosure reveals the vertical, text-labelled navigation in a bounded scroll area. Escape closes from either the open menu or its trigger and returns focus; same-page hash navigation transfers focus to the destination after closing. Cards and modal contents remain within the viewport; the rule modal scrolls inside its bounded panel on short screens.

The rule modal traps keyboard focus, returns focus to its opener, closes on Escape or Cancel, and dims the recognizable page behind it. Account tabs expose one form at a time and support arrow, Home, and End keys. Nonsensitive preview drafts live only in page memory; password values are never written to storage.
